DFA Architecture & Formal 5-Tuple

M = (Q, Σ, δ, q0, F)
States (Q) {q0, q1, q2, q3, q4, q5, q_word} (7 states)
Alphabet Classes (Σ) {E, R, O, OTHER_WORD, NON_WORD} (5 partitions)
Start State (q0) q0 (At word boundary / scanning)
Accepting State (F) {q5} (Emits match on NON_WORD or EOF)
Trap State q_word (Inside non-matching word)
Boundary Behavior Rejects suffixes (ERRORS), prefixes (XERROR), alphanumerics

Academic Theory & Course Reference

24CS52 — Theory of Computations

1. Course Alignment & Case Study Objective

This implementation corresponds to Computer Science & Engineering 5th Semester Course Code 24CS52 (Theory of Computations), Case Study SET-E: "Log File Analysis Using Regular Expressions and DFA".

The objective is to analyze semi-structured system logs by pairing declarative regular expression pattern extractors with a formally designed Deterministic Finite Automaton (DFA) without relying on regex engines for the automaton component.

2. Regular Expression Specification (5 Patterns)

Date (DD-MM-YYYY)
\b(0[1-9]|[12][0-9]|3[01])-(0[1-9]|1[0-2])-(?:19|20)\d\d\b
Enforces 01-31 days, 01-12 months, and 1900-2099 years with explicit word boundary guards.
Time (HH:MM)
\b(?:[01]\d|2[0-3]):[0-5]\d\b
Standard 24-hour clock syntax (00:00 to 23:59).
IPv4 Address
\b(?:25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)(?:\.(?:25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)){3}\b
Strict octet range 0-255 across four dot-separated octets without leading extra digits.
ERROR Keyword
\bERROR\b
Case-sensitive whole-word token matching target for cross-validation with the DFA.
WARNING Keyword
\bWARNING\b
Case-sensitive whole-word warning token.

3. Formal DFA Definition M = (Q, Σ, δ, q0, F)

  • State Set (Q): {q0, q1, q2, q3, q4, q5, q_word}.
  • Alphabet Classes (Σ): Five disjoint character equivalence classes: 'E', 'R', 'O', OTHER_WORD (all other [a-zA-Z0-9_]), and NON_WORD (any delimiter or whitespace).
  • Start State (q0): The automaton begins at state q0 (word boundary).
  • Transition Function (δ): Explicit matrix mapping every (state, class) pair to a deterministic next state.
  • Acceptance Condition (F): State q5 accepts the candidate match if and only if followed immediately by a NON_WORD character or End-Of-File (EOF).

4. Algorithmic Complexity & Engineering Tradeoffs

Dimension Python re Engine Manual DFAErrorScanner
Theoretical Time Linear O(N) on these non-backtracking patterns; potential O(2^N) on vulnerable backtracking regexes. Strict linear O(N) deterministic scan guaranteed under all input permutations.
Empirical Execution Executed in compiled C (CPython _sre engine); typically fast in raw CPU cycles. Executed in interpreted Python byte-code (loop overhead per character).
Memory Footprint Precompiled regex byte-code in C heap. Constant O(1) state transitions using integer lookups.
Extensibility Trivial: change regex string (declarative). Requires re-computing states and transition matrix for new keywords.

5. Documented Limitations & Safeguards

  • Calendar Day Validation: Syntactic regex accepts syntactically valid calendar strings such as 31-02-2024, which require semantic date parsing to reject.
  • IPv4 Edge Cases: Regex matches dotted-decimal IPv4, but does not parse CIDR notations or IPv6 addresses.
  • DFA Specialization: Manual DFA recognizes only whole-word ERROR tokens; expanding to 5 patterns would require a generalized Aho-Corasick or lexer-generator DFA.
